# Cave kit, wave 2 (and 3): build status

Built by `Docs/blender/caves/wave2/` (all files `W2_*`, a copy-based generator: `W2_room.py`, `W2_v4.py`, `W2_v5.py` are snapshots of the
dripstone generator with a few hooks; the shapes are signed-distance caves in `W2_engine.py` / `W2_assets*.py`). This file is generated by
`W2_make_doc.py` from the measured result files in `wave2/results/` and is rewritten after every asset.

Plan: `CaveKit_Concept_30.md` (assets, sizes, openings, modes). Pipeline: `CaveKit_Handoff.md`. Nothing here edits the older generator files.

## How an asset is built (one command per asset)

```
Docs/blender/caves/wave2/W2_queue.sh <key> [steps]     steps: b build, c check, r report, p preview, e export   (default bcrpe)
```

1. `b` `W2_v5.py` (env `W2_ASSET=<key>`): the shape (SDF) -> void and outer shell (marching tetrahedra, voxel remesh) -> openings cut with the kit's
   exact 11-point 1.4 x 2.1 m profile (+ collar, sleeve stubs; dug openings keep the kit's timber frame) -> formations planned and merged by
   the v5 voxel remesh -> `plug_floor_slits` -> collider (inner skin only, buried faces dropped, decimated) -> `W2_<Name>_v5.blend`.
2. `c` `W2_check.py`: clearance / width / walkability on the COLLIDER (what the engine walks on) and a flood-fill leak test on the render mesh.
3. `p` `W2_preview.py`: renders into `Docs/blender/caves/previews/W2_<Name>_*.png` (plan with the roof cut, overview, walking views).
4. `e` `cave_export.py` (unchanged, run on the W2 blend): FBX (`_LOD0`, `UTM_`, empties `1`, `2`, ... with +Z out), `_MASK.tif` (UV set 2 mask, 2048),
   `_info.json` into `Assets/Tunnels/Cave/`.

Clearances used by the check (engine evidence: EoH's 1.571 m crouch and 0.899 m prone openings): crouch routes must keep 1.6 m, prone routes 0.92 m of headroom
over a corridor 1.3 m wide; walk routes: 1.5 m over a 1.2 m corridor AND 1.95-2.0 m over a 0.5 m wide centre line (the kit's own 1.4 m dug profile is 2.1 m high only on its centre line, 1.65 m at 0.6 m off it, minus the 0.12 m timber frames: a 2.0 m x 1.2 m walk corridor is impossible inside the kit's profile, so it is tested as these two numbers).
`route_clear_height` is the largest height that still connects the two openings with the required width, i.e. the bottleneck of the best route (measured on the
collider with vertical rays, so a vertical body: leaning walls cost width). Cells are 0.1 m (0.2 m for the halls). The 1.4 m standing sockets (3.2 m round each socket)
are exempt from the width test (kit standard). Design margins used: prone roof 1.22 m, crouch roof 1.88 m (the decimated collider and the roughening cost up to 0.1 m).

Generator findings worth knowing (found by this wave's checks, not fixed in the older files):
* v5 `transfer` copies the `collide` flag from the nearest pre-remesh face, so the rock round the root of a small stalactite (collide 0) lost its collider triangles: HOLES in
  the collider's roof or floor (rays through the roof). `W2_overrides.w2_collider` only drops separate small formations (fid > 0) now. The older rooms' colliders (20k tris) have
  the same holes where small formations stand; worth fixing in `cave_dripstone_v5.py` (keep the faces, or set collide 1 for every remeshed face).
* The stubs' outer skins that `split_inside` calls 'earth in earth' (MAT_HIDDEN -> MAT_EARTH) stay in the collider; `w2_collider` drops buried faces (normal ray hits a back face).

## What the user must do (import list)

Workbench picks up new FBX files in `Assets/Tunnels/Cave/` by itself while it runs (the first asset appeared as `.xob`, `.txo`, `_MASK.edds` without a click),
so normally the import is already done when you open the project. If not: in the Resource Browser right-click `Assets/Tunnels/Cave` -> reimport / register the new
`TT_Cave_*` and `TT_Brk_*` FBX files and their `_MASK.tif` (the tif needs an `.edds.meta`: `wb_resources register` on it, or right-click -> Register).

Then, from the addon root, once per batch:

```
python Docs/blender/caves/wave2/W2_finish.py all          # or one or more names
```

* before the import it writes only the prefab (`Prefabs/Tunnels/TT/<Name>.et` + `.et.meta`) pointing at the model by PATH (no GUID exists yet);
* after the import it writes `Assets/Tunnels/Cave/Data/<Name>.emat` (MatPBRMulti, the same layers as the existing rooms), patches the model's material assignments
  (for `TT_Brk_*` the dug tube takes the TT dug kit's own `TT_Earth.emat` and its timber `TT_Wood.emat`), and rewrites the prefab with the model's GUID and the dark house probe.

Prefab GUIDs: the `.et` files written before the import reference `"Assets/Tunnels/Cave/<Name>.xob"` without a GUID; run `W2_finish.py` again after the import (or save the prefab once in
Workbench) and the GUID is filled in. The prefab entity IDs are derived from the name, so they never change.

Then rebuild the tunnel catalog (the new prefabs are rooms / passages for the generator; the theme logic for `TT_Cave_*` / `TT_Brk_*` is the one from the concept doc, not yet compiled).

Other agents re-import tunnels at the same time: the FBX files of this wave only have NEW names, nothing existing was overwritten.

## Export notes (UV2 / LODs)

* `W2_export.py` is a copy of the new-rooms agent's `NR_export.py` (cave_export + a UV2 repair), snapshot of 2026-11-24. The repair gives every zero-area or overlapping mask triangle its own
  8 px cell in a FREE block of the atlas (an affine copy: the mask is baked from per-vertex values, so the cell holds exactly the right data) and repeats until nothing overlaps
  (the NR version used a reserved band and left a few hundred overlaps; mine takes free blocks). Checked on the exported FBX with `W2_uvcheck.py` (= NR_uvcheck.py) at the mask resolution (2048):
  zero-area, overlapping and negative-winding triangles are listed per asset above.
* No LODs are exported for these assets (`CAVE_LOD_MIN` is raised): the seam-protected LODs of the NR script only reached 65 percent on these small meshes and a plain decimate re-creates
  zero-area / stretched mask triangles. The assets are 80-280k triangles; a LOD chain is a later step.
