# Pale sandstone cliff variants (copies of the red cliffs)

Target colour #f3e3d0 (243,227,208). Originals are untouched; only new files were added under `Prefabs/Rocks/Cliffs/`.

## How the red was produced
Not baked: the red comes from the shared tiled layer BCRs (RockPorous, Sand, Scree, SandstonePale) plus `Color 0.791 0.703 0.703` on the `_terrain` emats. MASK/NMO per cliff are only weights/relief, so they are reused unchanged. Cut variants use `system/terrain/terrain_BCR` as layer 2; in the copies it is replaced by SandCream (BCR) and Sand_NMO.

## Created files
- `_Layers/CliffLayer_{RockPorous,Sand,Scree,SandstonePale}Cream_BCR.tif` + `.edds.meta` (new GUIDs). Same size/alpha (roughness) as the originals; the detail structure of the originals is kept (+-8 % luminance variation) with warm darker streaks (~#d9c2a3) in the dark parts. Layer means (sRGB): Rock 243,227,208; Sand 247,234,216; Scree 228,208,180 (darker, crevices); Pale 249,240,226 (lighter, weathered top). Generated by a throw-away script (scratchpad, not in the addon).
- Per cliff (13 base + 6 cut = 19): `<Asset>/Data/<Material>_Sandstone.emat` and `..._Sandstone_terrain.emat` (+ `.emat.meta`), where present for the red cliff. Terrain emats use `Color 1 1 1 1` (no red tint) and the Pale-Cream BCR. NMO/MASK/GlobalNMO are the original ones.
- Prefabs `Cliff_Base_<Name>_Sandstone.et` / `Cliff_Cut_<Name>_Sandstone.et` (+ `.et.meta`): inherit from the red prefab and only override `MeshObject.Materials` (MaterialAssignClass for the rock and `_terrain` slot). Same xob, no meshes duplicated.
  Names: CrimsonBadlandsRidge, CrimsonMesaCitadel, CrimsonMonolith, DesertFortress, DesertMesaFragment, DesertMonolith, ErodedCanyonWall, ErodedDesertCliffs, ErodedDesertEscarpment, ErodedSandstoneWall, ErodedSandstoneWall02, HorseshoeRidge, MesaOfStoneFaces (Base); CrimsonBadlandsRidge, CrimsonMesaCitadel, DesertFortress, ErodedCanyonWall, ErodedDesertCliffs, ErodedDesertEscarpment (Cut).
- Not done: CrimsonMesaCrown, CrimsonSentinel, ErodedRedstoneMonolith, WeatheredSandstone (their emats have no `.emat.meta`/GUID, so a prefab cannot reference them yet), CrimsonSpireCanyon (no prefab).

## Colour result (statistics, not an engine screenshot)
Layer textures x Color 1: see means above. Mask-weighted albedo of the visible rock (mask weights R/G/B, remainder base layer): CrimsonMesaCitadel #f3e4d1, ErodedDesertCliffs_cut #f4e5d2, HorseshoeRidge #f4e4d2, i.e. within +1 of #f3e3d0 per channel. Real in-engine colour will additionally depend on lighting, GlobalLayerGlobalAO / Cavity settings, and SatMapBlend of the terrain under the terrain slot. If it looks too bright/dull, tune via Color on the materials (can only darken).

## Use
Swap the prefab in the world/layer from `Cliff_Base_X.et` to `Cliff_Base_X_Sandstone.et` (or `Cliff_Cut_X` -> `Cliff_Cut_X_Sandstone.et`). The world/layer files were not changed.
