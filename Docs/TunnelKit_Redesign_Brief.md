# TT tunnel kit redesign: brief (user decisions, 2026-11-24)

Owner of the work: the clearance agent (a92d38198569328a5, `Docs/TunnelKit_Clearance.md`), folded in because the redesign supersedes its "fix".
Builder to copy and extend (never edit the originals): `Docs/blender/tunnelkit_build.py` (standing kit), `Docs/blender/tunnelkit_build_cp.py` (crouch/prone/transitions).

## What the user asked for
1. **Remove all wood** from the dug tunnels: the timber frames at the joints (FRAME_T/FRAME_L), the `TT_Wood` material, any wooden lining in junctions, rooms, entries, crouch/prone pieces and transitions. Only earth (and the ground material if used) remains. Update the material slots and the `.xob.meta` assignments accordingly.
2. **Floor-to-wall junction less 90 degrees, more organic**: a rounded blend (fillet) between the floor and the wall instead of the sharp corner, in the profile of every piece (walk radius about 0.3 m; crouch about 0.15; prone about 0.1; the user may want to tune it).
3. **Wider and higher walk tunnels in general** (decided): the shared joint ring becomes **1.6 m wide x 2.2 m high clear** (was 1.4 x 2.1), arched/rounded, the same for EVERY opening of every standing piece, so any opening still fits any opening (sleeves 0.25 m, solid shells, light tightness as before, no floor step at a joint).
4. **More variety in width and height between the joints, so it feels organic** (decided): inside a piece the clear width varies between **1.3 m (one player, necks) and 3.0 m (four players abreast)** and the clear height between **2.3 m and 3.2 m**. **Hard rule: the walkable height never drops below the assigned walk height (2.2 m at joints; use 2.3 m minimum in the body) anywhere along the route, and the width never below 1.3 m**, unless the user asks otherwise. The joint ring stays 1.6 x 2.2 at both ends (so necks narrower than 1.6 m and bulges wider are in the middle of a piece, smoothly blended back to the ring at the joints).
5. **Variants** (decided: 3 per shape): the shapes Straight_1, Straight_2, Straight_4, Curve_5, Curve_10, Curve_15, Turn90, Dogleg_L, Dogleg_R and Slope each get a standard version (the existing name, e.g. `TT_Straight_4`) and two new ones named `<Name>_A` (a neck: narrow, one player) and `<Name>_C` (wide: up to 3.0 wide / 3.2 high). Same joint ring, same plan geometry and sockets as the standard version, so they are interchangeable. Junction, Room, End and the entries get one version each (no wood, rounded floor-wall, new ring). TT_Straight_Narrow / TT_Straight_Wide / TT_Turn90_Wide keep their names (the generator's spline kinds use Contains("Narrow") / Contains("Wide")): re-dimension them consistently and say how they relate to the _A/_C variants.
6. **Crouch and prone** (decided: also widen a bit): TT_C_* and TT_P_* (and the S/C/P transitions, entries) lose the wood and get the rounded floor-wall corner; their clear widths grow a little (crouch about 1.2 -> 1.4 m, prone about 1.0 -> 1.2 m) with small width variation (about +-15%); their clear heights stay FIXED (1.6 m crouch, 0.92 m prone minimum). The S-side rings of TT_Trans_S_C / TT_Trans_S_P follow the new walk ring (1.6 x 2.2).
7. **Ask the user for each asset when unsure**: the agent cannot ask; it must list the open questions per asset in the doc and in its final report (the main session will ask the user), instead of guessing.

## How to work (phases, so the user can steer early)
- **Phase 1 (report after it):** build the new profile system (fillet, new ring, variation function with smooth blending to the ring at both ends, no wood), then ONLY `TT_Straight_4` (+ `_A`, `_C`), one `Curve`, `TT_Turn90`, `TT_Junction` and the crouch/prone straights as a sample set. Verify (numbers) and render previews (inside views, a joint, the floor-wall fillet, the neck and the wide bulge). Report with the open questions. Do NOT overwrite existing standing FBXs in Assets/Tunnels/TT yet: write the Phase 1 samples under new names or a staging folder outside Assets (e.g. Docs/blender/redesign_staging/) so nothing in the user's maps changes before approval.
- **Phase 2 (after the user approved Phase 1):** the full set, overwriting the standard pieces in place (same names, sockets, plan geometry, lengths) plus the new variants, prefabs for the new variants (copy a sibling prefab; the main session already added dark probe children to all non-cave TT prefabs and set m_bExposureControl 0, keep that pattern for the new prefabs: copy the sibling's probe block), `.xob.meta` patched like the siblings.

## Constraints (unchanged)
- Sockets/bones "1","2",... keep names, end-plane positions, +Z out; plan geometry (lengths, turn radius 1.8, dogleg shift) unchanged. If the wider profile forces a larger turn radius or a longer piece, STOP and report it (existing placements and the generator depend on it); do not change it silently.
- Light-tight: solid shells, sleeves overlapping 0.25 m, no single-sided faces, closed meshes.
- Verification (reuse the clearance measuring script): min clear height along the walking route (centre and +-0.3 m) >= 2.3 m in the body and >= 2.2 m at joints (walk), crouch >= 1.6 m, prone >= 0.92 m; clear width >= 1.3 m anywhere (walk), >= 1.6 m at walk joints; joint tests of two copies for every shape and every variant combination (A with B with C: the ring must match).
- The user must press "Rebuild TT catalog" after the import (new piece names appear). The generator's KindWeight treats `TT_Straight_1` / `TT_Straight_2` / names containing `Curve_` specially: the main session adapts it for the variants, the agent lists the new names.
- No edits to other agents' files (NR_, W2_, CP_), Scripts/, Docs/blender/caves/. No git commit/stash/reset/checkout. Blender jobs only with run_in_background, one at a time (other agents share the machine), no foreground poll loops, no Workbench MCP tools.
